## Project Overview

My work in AI model training involves writing challenging programming prompts, correcting model answers, and reviewing contributor tasks. That experience shaped LabelForge: a personal project focused on clear annotation workflows and useful feedback.

The application combines React, TypeScript, Django REST Framework, and PostgreSQL. Three roles share one task lifecycle, with the API responsible for checking both permissions and valid state changes.

## Task Lifecycle

The state machine describes the path a task can take:

```text
unclaimed → in-progress → submitted → approved
                                    ↘ rejected → in-progress
```

A task must be claimed before it can be submitted, and review actions apply to submitted work. Keeping these checks in the API makes the workflow consistent across interface actions and direct requests.

## Three Focused Workflows

**Annotators** claim tasks, select labels, and submit work. Customizable label buttons and keyboard shortcuts support repeated actions. When a task returns for revision, the review feedback stays with it.

**Reviewers** inspect submitted work and approve it or return it with an explanation. Clear feedback gives the annotator something specific to address on the next submission.

**Admins** manage projects and datasets, then use the dashboard to follow progress and quality trends.

JWT authentication and role-based permissions serve different purposes: authentication establishes who is making a request; permissions determine which actions that user may perform.

## Quality Dashboard

The dashboard can be filtered by project and includes:

- Per-annotator rejection rate, average time per task, and throughput.
- Daily approval charts to show progress over time.
- Label-distribution breakdowns to reveal how categories are being used.
- Completion and rejection rates across a project.

These measures support investigation. A change in rejection rate can prompt a review of guidelines, task difficulty, or feedback; the number alone does not explain the cause.

## Results and Next Steps

The annotation interface improved usability for 15+ reviewers and reduced revision requests by 30%. Connecting those interactions to the task state machine and quality dashboard made the review cycle easier to follow.

Further work could add text-span annotation, inter-annotator agreement measures, and exports that retain review metadata. I would also expand testing around simultaneous task claims and permission boundaries as the number of users grows.
